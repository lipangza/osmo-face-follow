# 架构说明

本文说明从摄像头画面到蓝牙指令的完整数据流、线程模型、控制律，以及每个模块的职责。
协议字节细节见 [PROTOCOL.md](PROTOCOL.md)。

---

## 1. 总体数据流

```
┌──────────────┐   YUV 帧    ┌──────────────┐   Mat   ┌──────────────┐
│ CameraX      │ ──────────▶ │ YuvToMat +   │ ──────▶ │ FaceDetector │
│ ImageAnalysis│  640×480    │ 旋转正立      │         │ (YuNet)      │
└──────────────┘             └──────────────┘         └──────┬───────┘
                                                             │ RawDetection
                                                             ▼
                                                    ┌──────────────────┐
                                                    │ FaceOffsetCalc   │
                                                    │ dx/dy/conf/pose  │
                                                    └────────┬─────────┘
                                                             │ FaceResult（主线程）
                                                             ▼
                          ┌─────────────────────────────────────────────────┐
                          │ MainActivity.onFaceOffset()                     │
                          │  · 更新 OverlayView / 读数                       │
                          │  · 记录 lastFaceSeenAt                          │
                          │  · 死区 → 曲线 → 低通 → followYaw                │
                          └───────────────────────┬─────────────────────────┘
                                                  │ 目标值（每帧更新）
                                                  ▼
                          ┌─────────────────────────────────────────────────┐
                          │ followTicker（30 ms 节拍，33 Hz）                │
                          │  · 判丢脸时长：保持 / 衰减 / 停                  │
                          │  · yaw 速度帧 → sendYawSpeedRaw()               │
                          │  · pitch 每 100 ms 步进 → sendPitchAngleStep()  │
                          └───────────────────────┬─────────────────────────┘
                                                  │ DUML 字节
                                                  ▼
                          ┌─────────────────────────────────────────────────┐
                          │ BleManager                                      │
                          │  · 正常队列 / 实时「只留最新」队列               │
                          │  · 按 MTU-3 分片写入 FFF5                        │
                          │  · FFF4 通知 → DumlStreamParser → ACK 日志       │
                          └─────────────────────────────────────────────────┘
```

要点：

- **检测与下发解耦**：检测跑在相机帧率上（受设备性能影响），下发固定在 33 Hz。
  这样云台命令频率稳定，不会因为某一帧检测慢而抖动。
- **只发最新指令**：实时控制走「旧帧丢弃」通道，队列不会越积越长；33 Hz 才等于实际执行频率。
- **丢脸不立刻停**：停止逻辑集中在 ticker 里按「距上次检出时间」处理，单帧漏检不会让云台急停急摆。

| 采集 | `camera/CameraXManager.kt` | 预览 + 逐帧分析；YUV→Mat、按传感器方向旋转正立；调用检测与偏移计算；计算检测图像 → 预览显示矩阵；可选把位图交给闭眼模块 |

## 3. 线程模型

| 线程 | 谁在上面跑 | 注意点 |
| --- | --- | --- |
| 主线程 | UI、`followTicker`、BLE 回调、写入完成 | ticker 只做轻量计算与入队，不做图像处理 |
| CameraX 分析线程（单线程） | YUV 转换、旋转、检测、偏移计算 | 每帧串行；检测耗时直接决定实际处理帧率 |
| BLE 写入 | 主线程发起，`onCharacteristicWrite` 驱动下一条 | 写入按队列串行，不并发 |
| MediaPipe 推理 | 相机分析线程（仅在闭眼开关打开时） | 与检测串行，会增加单帧耗时；关闭开关后零开销 |

BLE 写入采用「写一条 → 等回调 → 写下一条」的串行模型，避免 Android 蓝牙栈丢写。
实时控制帧入队时会清空尚未发出的旧帧，只保留最新一条。

## 4. 坐标空间与叠加对齐

三个空间必须分清：

1. **传感器空间**：相机原始方向（前置通常是横屏传感器）。
2. **检测空间**：`ImageAnalysis` 目标分辨率 `640×480`，已旋转为正立，左上角为原点。
   人脸框、关键点、偏移量都在这个空间里计算。
3. **显示空间**：`OverlayView` 与 `PreviewView` 同尺寸；`PreviewView` 自己会做
   `FIT_CENTER` 缩放、旋转和前置镜像。

`CameraXManager` 计算「检测空间 → 显示空间」的矩阵并交给 `OverlayView`，框与关键点用同一个矩阵，
所以旋转 90°/270°（实际检测图 480×640）时也能对齐。前置摄像头在显示侧额外做水平镜像。

归一化偏移定义为：

```
dx = (人脸中心 x - 画面宽/2) / (画面宽/2)   // 向右为正
dy = (人脸中心 y - 画面高/2) / (画面高/2)   // 向下为正
```

## 5. 控制律

### 5.1 yaw（速度闭环，开环姿态）

对每一帧检测结果：

```
a = |dx|
若 a <= 0.04：目标速度 = 0
否则：
    t = (a - 0.04) / (1 - 0.04)          // 归一化到 0..1
    目标速度 = t^1.6 × 1050 × SIGN       // 单位 0.1°/s
```

再按真实帧间隔做一阶低通：

```
alpha = 1 - exp(-dt / 45ms)
followYaw += (目标速度 - followYaw) × alpha
```

曲线含义：小偏移时非常柔和（`dx=0.2` 约 8°/s），大偏移时快速追上（`dx=1.0` 为 105°/s），
既避免静止时抖动，也避免人快速走开时跟不上。

下发时再限幅到 `±1200`（即 120°/s），由 ticker 以 33 Hz 发送。

### 5.2 pitch（相对角度步进）

俯仰不使用速度模式（实测无效），改为每 100 ms 发一条相对角度帧：

```
dy = offsetY，|dy| < 0.04 时视为 0
newIntegrated = clamp(pitchIntegrated + dy × 1.0° × SIGN, -45°, +45°)
step = newIntegrated - pitchIntegrated
若 |step| >= 0.1°：发送 value = step × 10（单位 0.1°）
```

- 软件包络 `±45°` 是相对「开启跟随时」的姿态累计，不碰官方机械限位。
- 丢脸时（`decay < 0.9`）不步进，避免云台继续抬/压。
- 积分只在发送成功后才更新，写失败不会造成虚假累计。

### 5.3 丢脸状态机

| 距上次检出 | yaw 行为 |
| --- | --- |
| `≤ 100 ms` | 全量下发当前速度 |
| `100–300 ms` | 线性衰减到 0（单帧漏检不至于急停） |
| `> 300 ms` | 发一次零速度，之后每秒补一次零速度 |
| 断连 | 立即关闭跟随，补零速度（能发就发） |

`followYaw` 在丢脸时**不清零**，避免遮挡一瞬间云台来回摆。

## 6. 闭眼锁屏链路

```
CameraX 分析帧（仅开关打开时）
   → Bitmap
   → MediaPipe Face Landmarker（Face Mesh + blendshape）
   → EAR（6 点几何）与 eyeBlinkLeft/Right 分数
   → 双眼闭合判定（分数 ≥ 0.60 或 EAR 低于阈值）
   → EyeClosureGate：持续 1.35 s 触发，触发后冷却 8 s
   → 设备管理员 lockNow()
```

- 未激活设备管理员时，界面明确提示「闭眼不会锁屏」，不伪造成功状态。
- 脸太小（面积比 < 0.08）时不判定，避免远处误触发。
- 关闭开关后不挂帧回调，不产生推理开销。

## 7. 启动顺序

```
onCreate
 ├─ 初始化 OpenCV
 ├─ 初始化闭眼模块（读持久化开关）
 ├─ 初始化跟随开关（默认关闭）
 ├─ 检查权限
 │    ├─ 相机已授权 → 立即启动链路
 │    └─ 缺失 → 申请（蓝牙缺失只降级 BLE，不阻塞相机）
 └─ prepareAndStart()
      ├─ ModelPrep.ensureModel()（IO 线程）
      ├─ 创建 FaceDetector
      ├─ 创建并启动 CameraXManager
      └─ 初始化 BleManager → 开始扫描
```

跟随开关只有连上云台才能打开；连接、断开、写入成功都会通过回调回到主线程更新 UI。

## 8. 设计取舍

- **为什么不用官方 SDK**：官方移动 SDK 不覆盖 Osmo Mobile SE 的人脸跟随控制，
  且引入 SDK 会带来激活与账号依赖；本项目只需要 BLE 写帧，自建协议层更小更可控。
- **为什么固定 33 Hz**：BLE 写入在多数手机上稳定在 30–50 Hz；再高会排队，反而增加延迟。
- **为什么用「只留最新帧」**：跟随是姿态纠偏，过期的速度指令没有意义。
- **为什么 yaw 用速度、pitch 用角度**：实测速度帧对 pitch 无响应，角度帧对 pitch 有效。
- **为什么保留检测与下发的解耦**：检测帧率随设备波动，固定节拍能让云台运动更平滑。
